# テスト手順

## 自動テスト

作業フォルダーで実行します。

```powershell
node unit-test-v2.cjs
```

成功時は `"passed": true` が表示されます。

自動テスト対象:

- GitHub更新channelの形式検証とバージョン数値比較
- オンライン導本辞書・第一次収縮モデルの非破壊統合
- 更新確認UIとGitHub Releases導線
- 実測`start_dungeon`成功による導本所持数・前探索ランタイムの確定リセット
- 新規探索通知によるルートキャンバス・推奨手順・収縮表示の即時初期化
- 新探索遷移中に遅延した旧field captureの拒否と、T0初期MAPによる計算再開
- 同一戦闘での累計与ダメージ保持
- 同一 `raid_id` のstart再受信によるリセット防止
- ページリロード後の同一戦闘状態復元
- index欠落を含む保存済みキャラクター別前ターン状態の正規化
- アビリティ結果の現在ターン即時加算
- 通常攻撃後の現在→前ターン移動
- 次ターンの現在値リセット
- 新規戦闘だけ全値リセット
- キャラクター別帰属
- formationに基づくフロントキャラクター限定表示
- 所有者不明ダメージの誤帰属防止
- `n.n万`、`n.n億` 表示
- formationによるフロント判定
- 導本選択肢に表示された全候補と効果名の永続化
- 全タブ共通の導本辞書取得トースト
- 生リザルトの`reward_type/detail[]`から導本名・status_id・icon_typeを復元
- 表示用`view.arcarum3RewardList`と生`reward_list`の重複統合
- ID 1〜100の空枠補完と、101以降・ID不明レコードの保持
- 導本の「すべて／未獲得／獲得済み／ID不明」表示切替
- 直近選択肢と直近獲得の独立したハイライト
- 導本レアリティの赤銅・白・金枠と、直近表示・獲得の緑ハイライト
- 導本確認ページの呪われた導本カテゴリ・効果名・アイコン番号取得
- 導本ハイライトの60秒失効と、メタ情報を持たない再観測時のランク・重複可否保持
- R1ショップ導本の通常50コイン・割引38コインの分離保存
- 最終日ボス前ショップのR1割増75コインの識別
- `action_type: 400`によるデメリット導本の即時獲得
- サーバー名の単語途中改行とDOM名の改行なしによる重複統合
- 浮遊城本体の一時座標で転移マスを有効現在地として維持
- 現在地欠落レスポンス後の宝箱消化済み保持

## 静的検証

```powershell
Get-ChildItem -Filter *.js | ForEach-Object { node --check $_.FullName }
Get-Content -Raw manifest.json | ConvertFrom-Json | Out-Null
```

## Chromeへの読み込み

1. `chrome://extensions/` を開く。
2. 拡張機能を再読み込みする。
3. Service Workerのエラーがないことを確認する。
4. GBFタブを再読み込みする。
5. サイドパネルを開く。
6. 「新機能テスト」タブへ切り替える。
7. `nodeList` と `nodeDescriptions` のJSONが自動取得されることを確認する。
8. 「取得」で再取得でき、「コピー」と「JSON保存」が機能することを確認する。
9. 「Ajax状態更新履歴」の「記録開始」を押し、ゲーム内で移動・戦闘・イベントを1回ずつ行う。
10. 「停止」を押し、各操作のURLと応答が履歴へ追加されることを確認する。
11. 候補欄と保存JSONの `candidates` から現在地・ターン・通貨・収縮状態を含むエンドポイントを確認する。
12. 「最適ルート」タブへ切り替え、現在地から設定半径内のノードと推奨経路が表示されることを確認する。

### Ajax状態更新履歴

- [ ] 「記録開始」で以前の履歴が消え、表示が「記録中」になる
- [ ] 移動・戦闘・イベント後にURL、要求、応答が時系列で記録される
- [ ] `current_node_id` / `pieceNodeId` がある応答は現在地候補として表示される
- [ ] `total_turn` / `elapsedTurn` がある応答はターン候補として表示される
- [ ] `possession_arcarum3_dungeon_point` / `dungeonShopPoint` がある応答は通貨候補として表示される
- [ ] `miasma_info`、残りターン、収縮ノードなどが収縮・瘴気候補として表示される
- [ ] 「停止」直前のAjaxまで履歴へ入り、停止後のAjaxは追加されない
- [ ] コピーおよびJSON保存した履歴を開ける
- [ ] 履歴の開始・停止・クリアが戦闘集計へ影響しない
- [ ] `move_node` の `after_current_node_id` が現在地候補、`before_current_node_id` が移動元候補として表示される
- [ ] 通常イベントを離れた直後、リロードなしで移動元が空白になり、推奨ルートへ再度含まれない
- [ ] 宝箱を離れた直後、訪問済み反映が遅い場合も元の宝箱へ戻る推奨が出ない
- [ ] `move_node`応答に現在地がない場合も、要求した到着nodeへ現在地が更新される
- [ ] 浮遊城本体の孤立ノードへ演出移動しても、MAP全体が消えず転移マスを基準に経路が表示される
- [ ] 浮遊城の選択結果後、ページをリロードせず転移マスからの経路表示へ戻る
- [ ] 特殊イベントまたは強敵を未消化のまま通過しても、そのマスが空白扱いにならない
- [ ] `node_list[].is_shrinking: false` が大量の候補として表示されず、`true` のノードだけが収縮対象候補になる
- [ ] 記録中のAjaxが「永続ログ」へ追記され、画面用60件を超えても古い通信が分割ファイルに残る
- [ ] 永続ログが約5MBごとに連番のJSONLファイルへ分割される
- [ ] 拡張機能のService Worker停止・再起動後も以前の永続ログ一覧を取得できる
- [ ] 永続ログの「保存」でJSONLファイルを開ける
- [ ] 「全削除」は確認後だけ全永続ログを削除する
